# 원문 접근 공식 경로 카탈로그 (뉴스 속 통계의 원출처를 자동으로 가져오는 합법 경로)

조사일: 2026-11-14. 공식 문서를 직접 확인한 항목과 제3자 자료·기억에만 근거한 항목을 구분해 적었다. "(미확인)"은 공식 문서로 검증하지 못했다는 뜻이다. 우회(UA 위장, 차단 회피) 경로는 넣지 않았다.

공통 메모: 공공데이터포털(data.go.kr) API는 회원가입 → 데이터별 '활용신청' → 마이페이지에서 서비스키 확인 순서다. 대부분 무료이고 즉시 승인되지만, 심의가 필요한 데이터는 며칠 걸린다. 개발계정 트래픽은 보통 하루 1,000~10,000건이고, 활용사례를 등록해 운영계정으로 바꾸면 늘어난다 — [플렉스튜디오 안내](https://flextudio.com/blog/koreadataportal-1), [elancer 안내](https://www.elancer.co.kr/blog/detail/1045), [금융위_KRX상장종목정보(개발 10,000)](https://www.data.go.kr/data/15094775/openapi.do). 하루 허용량을 넘기면 공통 오류코드 22가 나온다 — [data.go.kr 오류코드 예시](https://www.data.go.kr/catalog/15001697/openapi.json).

## 1. 보도자료 (정책브리핑·시도·국회·통합 API)

### Takeaway
정부 보도자료 전체를 한 번에 주는 통합 API는 이번 조사에서 공식 문서로 확인하지 못했다. 정책브리핑은 "모든 자료가 저작물이니 담당자와 사전 협의하라"고 안내한다. 국회사무처 보도자료와 KTV 게시판은 data.go.kr API로 나와 있다. 현실적인 경로는 data.go.kr의 기관별 보도자료 API를 쓰고, 없는 기관은 기관 RSS나 원문 링크를 쓰는 것이다.

### Cited Findings
- 정책브리핑(korea.kr)은 문화체육관광부 국민소통실이 운영한다. 브리핑룸 보도자료는 각 부처에서 연계로 자동 유입된다 — [korea.kr FAQ](https://m.korea.kr/etc/faq.do), [korea.kr FAQ(PC)](https://www.korea.kr/guide/faq.do)
- 저작권 안내는 두 가지가 섞여 있다. 저작권정책 페이지는 "공공저작물로서 별도 허락 없이 이용 가능"이라고 하면서, 사진(정부기관·연합뉴스)과 이미지(통로이미지)는 예외로 둔다 — [korea.kr 저작권정책](https://www.korea.kr/guide/copyRight.do). 반면 FAQ는 "모든 자료는 저작권법으로 보호되니 메뉴 담당자와 사전 협의 후 이용"하라고 한다 — [korea.kr FAQ](https://www.korea.kr/guide/faq.do). 두 안내가 충돌하므로, 대량 자동 수집 전에는 확인이 필요하다.
- '문화체육관광부 한국정책방송원_게시글 정보 조회 서비스'(data.go.kr)는 KTV 홈페이지 보도자료 등 게시판 글의 제목·내용·등록일·첨부파일·링크를 준다. REST/JSON, 무료, 실시간 갱신, 개발계정 10,000건이다 — [data.go.kr 15136860](https://www.data.go.kr/data/15136860/openapi.do). 단, 이것은 KTV 게시판이지 정책브리핑 전체 보도자료가 아니다.
- 문체부 e브리핑 메타데이터(자원명·등록일·주제분류·핵심주제어)가 data.go.kr에 등록돼 있고, 접근 URL은 문화정보원(culture.go.kr) OpenAPI다 — [data.go.kr 15152537](https://www.data.go.kr/biz/dcat/metadata/15152537.do), [문화공공데이터광장 OpenAPI 안내](https://www.culture.go.kr/data/openapi/openapiInfo.do)
- 국회사무처 보도자료 API는 data.go.kr에 '국회 국회사무처_보도자료'로 있다 — [data.go.kr 15077348](https://www.data.go.kr/en/data/15077348/openapi.do)
- 공공기관 단위 보도자료 API도 data.go.kr에 따로따로 있다(예: 대전교통공사 보도자료 게시판) — [data.go.kr 15125451](https://www.data.go.kr/en/data/15125451/openapi.do)

### Inferences
- 정책브리핑 보도자료 API를 따로 찾지 못했다. 그러니 "부처 보도자료 원문"은 (a) data.go.kr에서 기관명+보도자료로 API를 찾고, (b) 없으면 해당 부처·korea.kr의 공개 RSS/원문 URL을 링크로만 제시하는 방식이 안전하다. 본문 전체를 재배포하지 말고 링크와 짧은 인용만 쓴다.
- 보도자료 API가 있으면 첨부파일(HWP/PDF) 링크까지 받을 수 있다. 그러면 뉴스 수치가 첨부 표에만 있는 경우에도 검증 범위를 넓힐 수 있다.

### Gaps
- data.go.kr에 '정책브리핑 보도자료' 오픈API(예: 기관코드 1371000)가 있는지 공식 페이지로 확인하지 못했다. 검색에 나오지 않았고, metadata 페이지 15101213은 열다가 시간 초과로 실패했다.
- 17개 시도(경기도 gnews 등) 보도자료 API는 조사하지 못했다. 시도마다 열린데이터광장(서울 data.seoul.go.kr, 경기데이터드림 등)에서 따로 찾아야 한다.
- 국회사무처 보도자료 API의 필드(본문 포함 여부)와 트래픽은 확인하지 못했다.

## 2. 통계 (KOSIS, e-나라지표, 국가데이터처 보도자료, 한국은행 ECOS)

### Takeaway
KOSIS와 ECOS는 둘 다 무료 인증키로 통계표 숫자를 구조화된 형태(JSON)로 준다. 그래서 뉴스 수치("○○ 6.5% 증가")를 통계표 값과 직접 맞춰 볼 수 있다. 호출 한도는 둘 다 공식 문서에서 확인하지 못했다.

### Cited Findings
- KOSIS OpenAPI 개발가이드는 kosis.kr/openapi/devGuide/ 아래에 있다(통계목록, 통계자료, 통계설명, 메타 등) — [devGuide 0101](https://kosis.kr/openapi/devGuide/devGuide_0101List.do), [devGuide 0201](https://kosis.kr/openapi/devGuide/devGuide_0201List.do), [devGuide 0401](https://kosis.kr/openapi/devGuide/devGuide_0401List.do), [devGuide 0701](https://kosis.kr/openapi/devGuide/devGuide_0701List.do)
- 통계자료 호출은 `statisticsParameterData.do?method=getList`에 apiKey, orgId, tblId, itmId, objL1… 파라미터를 붙인다. 키는 KOSIS OpenAPI 사이트에서 무료로 활용신청해 받는다 — [CRAN kosis 패키지 README](https://archive.linux.duke.edu/cran/web/packages/kosis/readme/README.html), [k-skill kosis 문서(제3자)](https://raw.githubusercontent.com/NomaDamas/k-skill/main/docs/features/kosis-stats.md)
- KOSIS 오류코드 예: 10=키 누락, 11=키 만료(제3자 정리) — [k-skill kosis 문서](https://raw.githubusercontent.com/NomaDamas/k-skill/main/docs/features/kosis-stats.md)
- 한국은행 ECOS: ecos.bok.or.kr/api에서 약관 동의 후 무료로 인증키를 신청한다. StatisticSearch 형식은 `/api/StatisticSearch/{키}/json/kr/{시작}/{끝}/{통계표코드}/{주기}/{시작일}/{종료일}`이다 — [wikidocs ECOS 인증키 신청](https://wikidocs.net/144514), [CRAN ecos README](https://search.r-project.org/CRAN/packages/ecos/readme/README.html)
- ECOS 한도를 "약 1,000건/일"로 적은 곳이 있지만 제3자(Apify) 설명이다 — [Apify BOK actor](https://apify.com/nexgendata/korea-bok-monetary-policy-ecos)

### Inferences
- 뉴스가 "통계청(국가데이터처) 발표"라고 하면 대개 KOSIS 통계표로 숫자를 다시 확인할 수 있다. 다만 orgId/tblId를 알아야 하므로 통계목록 API(또는 통합검색)로 표를 먼저 찾는 단계가 필요하다.
- 보도자료 당일 수치는 KOSIS 반영이 늦거나, 계열이 잠정치에서 확정치로 바뀌어 숫자가 달라질 수 있다. 작은 차이를 바로 '불일치'로 판정하지 않도록 한다.

### Gaps
- KOSIS·ECOS 일일 호출 한도의 공식 수치는 확인하지 못했다(ECOS 10만 건 설은 검증 실패).
- e-나라지표 전용 OpenAPI가 있는지 확인하지 못했다(KOSIS 공유서비스에 통합됐을 가능성이 있다, 미확인).
- 국가데이터처(구 통계청) 보도자료 전용 API는 찾지 못했다.

## 3. 기업 (OpenDART, KRX, KIND, SEIBro)

### Takeaway
OpenDART는 공시 목록·원문 외에도 재무 수치 API(단일회사 주요계정/전체 재무제표)가 있어 실적 숫자를 구조화해서 맞출 수 있다. KRX는 2024년 이후 공식 Open API(openapi.krx.co.kr)를 운영한다. 키당 하루 10,000건, 비상업 목적만 허용, "KRX 통계정보" 출처 표시 의무가 붙는다. SEIBro 해외주식 결제 통계 API는 공식 경로를 확인하지 못했다.

### Cited Findings
- OpenDART 재무 API로는 `fnlttSinglAcnt`(단일회사 주요계정)와 `fnlttSinglAcntAll`(단일회사 전체 재무제표)이 쓰인다. 상태코드 013은 데이터 없음이다. 연결(CFS)이 없으면 별도(OFS)로 다시 조회하는 패턴이 흔하다 — [AlgoLab 블로그(제3자)](https://algolab.co.kr/blog/dart-opendart-financial-statement-api-lag-2026), [korea-stock-mcp 코드](https://glama.ai/mcp/servers/@jjlabsio/korea-stock-mcp/blob/81fe2726c81d1ceb4da58abf17bbb2c46dae388f/src/dart/get-financial-statement.ts)
- OpenDART 한도는 인증키당 하루 20,000건이고, 넘기면 상태코드 020이다(제3자 여러 곳이 같은 수치) — [AlgoLab](https://algolab.co.kr/blog/dart-opendart-financial-statement-api-lag-2026), [k-dart 스킬](https://www.remoteopenclaw.com/skills/nomadamas/k-skill/k-dart)
- KRX OPEN API 약관 — [openapi.krx.co.kr 약관](https://openapi.krx.co.kr/contents/OPP/INFO/OPPINFO005.jsp)
  - 인증키를 신청해야 하고(제5조), 유효기간은 1년이며 연장할 수 있다. 12개월 동안 쓰지 않으면 키가 삭제될 수 있다(제8조).
  - "키 1개당 최대 요청 수는 하루 10,000건"(제8조).
  - 비상업 목적만 허용하고, 결과를 제3자에게 유료로 제공하는 것도 금지한다(제6조). 결과를 바꾸거나 다른 내용을 끼워 넣으면 안 되고, 제3자에게 데이터를 넘기는 것도 금지한다(제6·11조).
  - API 결과를 쓴 화면에는 "KRX 통계정보" 이용을 표시해야 한다(제10조).
  - 분류: 지수, 주식, 증권상품, 채권, 파생상품, 일반상품, ESG.
- 금융위원회_KRX상장종목정보(data.go.kr)는 KRX 자체가 아닌 별도 API이고, 개발계정 10,000건이다 — [data.go.kr 15094775](https://www.data.go.kr/data/15094775/openapi.do)
- pykrx는 공식 API가 아니라 KRX 웹 데이터를 긁어 오는 라이브러리다 — [pykrx GitHub](https://github.com/sharebook-kr/pykrx)
- KRX는 2025년 5월 대용량 데이터 다운로드용 클라우드 서비스를 출시했다 — [Korea Times](https://www.koreatimes.co.kr/business/20250523/korea-exchange-launches-cloud-service-for-large-scale-data-downloads)

### Inferences
- 실적 기사(매출·영업이익 ○○억원)는 OpenDART `fnlttSinglAcnt`로 숫자를 직접 맞출 수 있다. 우리 서비스는 이미 OpenDART를 쓰므로 추가 비용 없이 확장할 수 있다.
- 우리 서비스가 상업 서비스로 분류되면 KRX API는 약관상 쓰기 어려울 수 있다. 해커톤 시연(비상업)에는 쓸 수 있겠지만, 출처 표시 "KRX 통계정보"는 꼭 넣어야 한다.
- pykrx는 사실상 스크래핑이므로 '공식 경로만' 원칙에 맞지 않는다.

### Gaps
- OpenDART 공식 개발가이드(opendart.fss.or.kr/guide)를 직접 열어 보지 못해, 20,000건 한도와 주요사항보고서(DS005 계열) 엔드포인트 목록은 제3자 자료와 기억에만 근거한다.
- KIND 저PBR 명단(밸류업 공시 등)의 공식 API는 찾지 못했다. KRX Open API 분류에도 해당 항목이 보이지 않았다.
- SEIBro(한국예탁결제원) OpenAPI, 해외주식 순매수·결제 통계 API는 공식 페이지를 찾지 못했다. data.go.kr에서 '예탁결제원'으로 다시 찾아봐야 한다.
- KRX API의 개별 엔드포인트(일별 시세 등) 명세는 확인하지 않았다.

## 4. 가격·시세 (오피넷 유가, KRX 시세)

### Takeaway
오피넷 Open API는 회원가입 후 받는 인증키(certkey)로 시도별 현재 평균가(`avgSidoPrice.do`)를 준다. 주간 평균가 API는 공식 페이지에서 확인하지 못했다. 뉴스에 나오는 "주간 평균 1,855.1원"은 오피넷 주간 동향 발표 수치일 가능성이 높아서, 현재가 API로는 같은 숫자를 맞추기 어렵다.

### Cited Findings
- `https://www.opinet.co.kr/api/avgSidoPrice.do`의 파라미터: certkey(필수, "공사에서 부여한 인증키"), out(xml/json), sido(선택), prodcd(B027 보통휘발유, D047 자동차경유, B034 고급휘발유, C004 실내등유, K015 부탄). 응답 필드: SIDOCD, SIDONM, PRODCD, PRICE, DIFF(전일 대비). 인증키 발급은 /user/custapi/openApiNew.do — [오피넷 Open API 상세](https://www.opinet.co.kr/user/custapi/openApiInfoDtl.do?apiId=6)
- 같은 페이지에 무료 여부와 호출 한도는 나와 있지 않다. 사이트 저작권정책은 상업적 이용에 사전 협의와 출처 표시를 요구한다(API 데이터에도 적용되는지는 불명확) — [오피넷 Open API 상세](https://www.opinet.co.kr/user/custapi/openApiInfoDtl.do?apiId=6)
- 오피넷 Open API는 2015년 12월 회원가입제로 시작했고, 당시 '주유소 평균가격' 등 10개 API였다 — [뉴스핌 2015-11-30](https://newspim.com/news/view/20151130000349)
- 한국석유공사 '시도별 평균가격(현재)' API는 data.go.kr에도 등록돼 있다 — [data.go.kr 15163154](https://www.data.go.kr/catalog/15163154/openapi.json)
- 언론은 오피넷을 인용해 주간 전국 평균을 보도한다(예: 2026년 1월 첫째 주 휘발유 1,720.7원) — [경향신문 2026-01-17](https://www.khan.co.kr/article/202601171642001/)

### Inferences
- "주간 평균" 검증은 (a) 오피넷의 최근 7일 일별 평균 API(있다면)를 받아 우리가 직접 주간 평균을 내거나, (b) 오피넷 '주간 유가 동향' 보도자료 원문 링크를 제시하는 방식이 현실적이다. (a)로 계산한 값은 공식 주간 집계와 기준(요일·가중)이 달라 소수점이 다를 수 있다.
- data.go.kr 경로를 쓰면 data.go.kr 약관(공공누리 등)으로 이용 조건이 정리되므로 오피넷 직접 키보다 약관 해석이 쉽다.

### Gaps
- 오피넷의 `avgRecentPrice.do`(최근 7일 전국 평균), `avgLastWeek.do`(지난주 주간 평균) 같은 엔드포인트가 있는지 공식 페이지로 확인하지 못했다(기억에만 있음, 미확인). 오피넷 Open API 목록 페이지에서 직접 확인해야 한다.
- 오피넷 키의 무료 여부, 일일 한도, 자동 이용 허용 여부는 확인하지 못했다(문의처: 1688-5142).

## 5. 기타 자주 인용되는 출처 (심평원, 대학알리미, 국회 의안, 경찰청, 여론조사심의위)

### Takeaway
열린국회정보(open.assembly.go.kr)는 무료 키로 의원 발의 의안 등을 주지만 범위에 한계가 있다(정부 제출 법안·회의록은 API에 없다는 정리가 있다). 심평원 질병 통계("건선 환자 15만4987명" 같은 수치)용 공식 API는 이번 조사에서 확인하지 못했다. 나머지(대학알리미, 경찰청 범죄통계, 여론조사심의위)도 공식 API를 확인하지 못했다.

### Cited Findings
- 열린국회정보: 회원가입(이메일 인증) 후 마이페이지에서 API 키를 무료로 받는다. 호출은 `open.assembly.go.kr/portal/openapi/{서비스ID}?KEY=…&Type=json&pSize=…&AGE=22` 형식이다 — [국회 데이터 튜토리얼 1장](https://kyusik-yang.github.io/assembly-tutorial/01-setup.html)
- 같은 튜토리얼의 정리(제3자)는 이렇다. 의안은 16~22대이고 의원 발의만 대상이다. 정부 제출 법안, 회의록, 국민청원은 API에 없고, 표결은 집계 수준이다 — [국회 데이터 튜토리얼](https://kyusik-yang.github.io/assembly-tutorial/)
- data.go.kr에도 국회 관련 API가 여러 개 등록돼 있다 — [data.go.kr 15126134](https://data.go.kr/data/15126134/openapi.do)
- 심평원 '상병마스터'는 파일데이터로 연 1회 갱신된다(질병코드 사전이지 환자 수 통계가 아님) — [data.go.kr 15067467](https://www.data.go.kr/data/15067467/fileData.do)

### Inferences
- 심평원 질병별 환자 수 기사는 대개 심평원 보도자료나 보건의료빅데이터개방시스템(opendata.hira.or.kr)의 '국민관심질병통계'에서 나온다. 공식 API가 없다면 원문 링크 제시가 최선이다(미확인).
- 예비심사보고서 같은 의안 문서는 의안정보시스템 원문 PDF 링크를 의안번호로 제시하는 방식이 현실적이다.

### Gaps
- 심평원 질병 통계 API(data.go.kr '질병정보서비스'의 오퍼레이션명, 환자 수 제공 여부)를 확인하지 못했다.
- 대학알리미 공시 API, 경찰청 범죄통계 파일데이터, 중앙선거여론조사심의위원회 API는 이번 조사에서 다루지 못했다(검색 예산 부족).
- 열린국회정보의 보도자료·예비심사보고서 서비스 ID는 확인하지 못했다.

## 6. 해외 (BLS, FEC, Eurostat, INSEE, 미 국무부)

### Takeaway
BLS·FEC·Eurostat은 모두 공식 API로 자동 접근을 허용한다. BLS는 무료 v2 키로 하루 500쿼리, FEC는 api.data.gov 키로 시간당 1,000건이다. Eurostat은 키가 필요 없다. 시리즈 ID나 데이터셋 코드를 알면 "PPI 6.5% y/y" 같은 수치를 원값으로 다시 계산해 볼 수 있다.

### Cited Findings
- BLS Public Data API — [BLS API FAQ](https://www.bls.gov/developers/api_faqs.htm), [BLS API features](https://www.bls.gov/bls/api_features.htm)
  - v2(등록): 하루 500쿼리, 쿼리당 50시리즈·20년.
  - v1(미등록): 하루 25쿼리, 25시리즈·10년.
  - 공통 속도 제한은 10초당 50요청이다.
  - 등록은 이메일·기관명·CAPTCHA로 하고, labstat@bls.gov에서 키가 메일로 온다. 1년에 한 번 이상 갱신해야 한다.
  - BLS는 시리즈 ID 카탈로그를 따로 관리하지 않는다.
- BLS 키는 POST JSON 본문의 `registrationkey`로 보내고, 엔드포인트는 `https://api.bls.gov/publicAPI/v2/timeseries/data/`다 — [blsR 문서](https://packages.oit.ncsu.edu/cran/web/packages/blsR/refman/blsR.html)
- api.data.gov(FEC 포함): 기본 한도는 키당 시간당 1,000건이다. DEMO_KEY는 IP당 시간당 30건, 하루 50건이다. 응답 헤더 X-RateLimit-Remaining으로 남은 양을 알 수 있고, 넘기면 429 OVER_RATE_LIMIT이다 — [api.data.gov developer manual](https://api.data.gov/docs/developer-manual)
- FEC는 요청하면 시간당 7,200건 키를 줄 수 있다고 안내한 바 있다(오래된 자료라 현재와 다를 수 있음) — [APIs.guru fec.gov](https://apis.guru/apis/fec.gov)
- Eurostat Statistics API는 공개 REST이고 JSON-stat 2.0을 돌려준다(SDMX-CSV/TSV/SDMX-ML도 있음). 등록 절차는 보이지 않는다 — [Eurostat API introduction](https://ec.europa.eu/eurostat/en/web/user-guides/data-browser/api-data-access/api-introduction), [Eurostat API getting started](https://ec.europa.eu/eurostat/en/web/user-guides/data-browser/api-data-access/api-getting-started/api)
- INSEE BDM은 SDMX 2.1 API다. 쿼리당 idbank 약 400개까지 받을 수 있다 — [CRAN insee vignette](https://search.r-project.org/CRAN/packages/insee/vignettes/insee.html). "키 없음, 분당 30회"라는 설명은 제3자 PHP 패키지의 것이다 — [packagist omnistate/insee](https://packagist.org/packages/omnistate/insee)

### Inferences
- BLS 웹사이트는 봇 접근을 막지만 API는 공식적으로 열려 있다. 그러니 BLS 수치 검증은 반드시 API로 해야 한다. PPI 최종수요 y/y 같은 값은 지수 원값을 받아 12개월 전 값과 비교해 계산해야 한다(API가 계산값을 줄 수도 있으나 미확인).
- 미 국무부 보도문은 공식 API를 찾지 못했다. state.gov 원문 링크만 제시하는 것이 안전하다(미확인).

### Gaps
- BLS 이용약관에서 상업적·자동 이용 조항을 직접 보지 못했다. FAQ는 API 사용 자체를 전제로 한다.
- INSEE 공식 API 포털(portail-api.insee.fr)의 현재 인증·한도 조건은 확인하지 못했다.
- 미 국무부 API 유무는 조사하지 못했다.

## 7. 뉴스 속 특정 수치를 이 경로로 검증할 수 있는가 (요약 판단)

### Takeaway
숫자 자체를 API로 다시 받아 맞출 수 있는 곳은 KOSIS, ECOS, OpenDART 재무, KRX(비상업), BLS, FEC, Eurostat이다. 보도자료 원문이나 주간 집계처럼 '발표문 속 숫자'는 대부분 API가 아니라 원문 링크로 검증해야 한다.

### Cited Findings
- 유가 "주간 평균 1,855.1원": 확인된 API는 현재 시도별 평균(`avgSidoPrice`, 전일 대비 DIFF)뿐이라, 주간 수치를 그대로 맞추기는 어렵다 — [오피넷 Open API 상세](https://www.opinet.co.kr/user/custapi/openApiInfoDtl.do?apiId=6)
- "PPI 6.5% y/y": BLS v2 API로 해당 시리즈를 20년치까지 받을 수 있다 — [BLS API FAQ](https://www.bls.gov/developers/api_faqs.htm)
- KRX 시세·지수: 키당 하루 10,000건, 비상업 조건 — [KRX 약관](https://openapi.krx.co.kr/contents/OPP/INFO/OPPINFO005.jsp)

### Inferences
- 우선순위를 제안하면 이렇다. ① 이미 쓰는 OpenDART에 재무 API 추가, ② KOSIS·ECOS(무료, 숫자 직접 대조), ③ BLS/FEC/Eurostat(해외 기사), ④ 보도자료는 data.go.kr 기관별 API + 원문 링크, ⑤ 오피넷·심평원·SEIBro는 공식 API 범위를 확인한 뒤 결정.
- 잠정치에서 확정치로 바뀌는 수정, 반올림, 기준 시점 차이 때문에 API 값과 기사 숫자가 조금 다를 수 있다. 허용 오차와 "발표 당시 값" 표시가 필요하다.

### Gaps
- "건선 환자 15만4987명"을 공식 API로 바로 검증하는 경로는 찾지 못했다(심평원 공식 API 미확인).
