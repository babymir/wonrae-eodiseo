# 수치·통계 주장 검증과 출처 추적: 학술 연구·데이터셋·오픈소스 조사 (2026-11 기준)

> 범위: 「원래 어디서?」(한국어 기사 속 수치 문장 → 원 보고서/보도자료 PDF → 정확한 쪽·문장 → 일치 / 표현 변경(기간·대상·단위·용어) / 기자 계산 수치(재료 포함) / 통계표·원자료 인용 / 원문에 없음 / 못 찾음)와 겹치는 학술·오픈소스 작업.
> 표기: **[확인]** = 이번 조사에서 검색 결과나 원문 페이지로 확인함. **[미재확인]** = 조사자의 기존 지식이며 이번 세션에서 원문을 다시 열어 보지 못함. 인용하기 전에 확인이 필요함.

## Q1. 수치 주장 검증 시스템·벤치마크 (QuanTemp, StatCheck, Scrutinizer, AggChecker, ClaimBuster, FEVEROUS, TabFact, SciFact, CheckThat!, Aletheia 등)

### Takeaway
수치 주장 검증 연구는 크게 두 갈래이다. 하나는 웹 증거 조각을 보고 참/거짓/상충만 판정하는 벤치마크(QuanTemp, QuanTemp++, CheckThat! 2025 Task 3)이고, 다른 하나는 주장을 정해진 통계 DB나 표에 비춰 맞는지 계산하는 시스템(StatCheck, AggChecker, Scrutinizer, Aletheia, TabFact/TabVer)이다. 확인한 범위에서 **기사 문장의 원 보고서 PDF를 찾아 쪽·문장 단위로 짚어 주는 작업**, 그리고 **"표현 변경 / 기자 계산 / 통계표 인용"처럼 출처와 어떤 관계인지 분류하는 작업**을 함께 하는 시스템은 찾지 못했다. 한국어를 다루는 것도 없다.

### Cited Findings
**QuanTemp (2024)** [확인]
- 수치·시간 표현이 든 실제 주장 15,514건을 팩트체크 사이트에서 모은 오픈도메인 벤치마크이다. 증거 코퍼스에서는 팩트체크 사이트를 빼서 정답 증거가 새지 않게 했다. — [arXiv 2403.17169](https://arxiv.org/pdf/2403.17169)
- 가장 좋은 기준 모델의 macro-F1은 58.32이다. — [paperswithcode 미러](https://physics.paperswithcode.com/paper/numtemp-a-real-world-benchmark-to-verify)
- 증거 코퍼스는 웹 조각 약 42만 3천 건이다(2차 리뷰 사이트 수치). — [Moonlight 리뷰](https://www.themoonlight.io/review/quantemp-a-real-world-open-domain-benchmark-for-fact-checking-numerical-claims)
- 주장 출처는 팩트체크 기관 45곳, 라벨 비율은 False 57.93% / Conflicting 23.27% / True 18.79%이다. 2차 출처 수치이고 원 논문으로 확인하지 못했다. — [alphaxiv](https://alphaxiv.org/benchmarks/delft-university-of-technology/quantemp)
- 라벨은 참/거짓/상충 3가지뿐이다. 원문 위치를 찾거나 의미 변화 유형을 나누는 과제는 없다. — [arXiv 2403.17169](https://arxiv.org/pdf/2403.17169)

**QuanTemp++ (2025-10)** [확인]
- Venktesh, Prabhu, Anand가 썼다. 자연 발생 수치 주장, 오픈도메인 코퍼스, 주장 분해(claim decomposition)로 모은 증거를 담았고, 시간 누수(temporal leakage)를 줄이도록 라벨을 붙였다. 코드는 https://github.com/VenkteshV/QuanTemp_Plus 에 있다. — [arXiv 2510.22055](https://arxiv.org/abs/2510.22055)
- 초록에는 증거를 정확한 쪽·문장 단위로 짚는다는 말이 없다. — [arXiv 2510.22055](https://arxiv.org/abs/2510.22055)

**CLEF CheckThat! 2025 Task 3 "Fact-Checking Numerical Claims"** [확인]
- 수치·시간 표현이 든 주장과 검색된 증거 조각을 받아 참/거짓/상충을 판정하는 과제이다. 영어 데이터는 15,514건이고, 주장마다 BM25 상위 100개 문서가 붙어 있다. 언어는 영어·스페인어·아랍어이다. — [CEUR Vol-4038 paper 53](https://ceur-ws.org/Vol-4038/paper_53.pdf), [CheckThat 2025 overview(arXiv 2503.14828)](https://arxiv.org/pdf/2503.14828.pdf)
- 전체 개요 논문은 LNCS 16089권 199–223쪽(2026)에 실렸다. LLM을 미세조정하면 성능이 오르지만 최고 시스템도 상한에 못 미친다. — [TU Delft 저장소](https://repository.tudelft.nl/record/uuid:37199903-2543-4794-9a1d-f12a568c7e90), [HBKU 기록](https://elmi.hbku.edu.qa/en/publications/overview-of-the-clef-2025-checkthat-lab-task-3-on-fact-checking-n/)
- 참가 시스템 예: ClaimIQ는 LoRA로 미세조정한 LLaMA가 가장 좋았지만 테스트 세트에서는 일반화가 떨어졌다. — [arXiv 2509.11492](https://arxiv.org/pdf/2509.11492)
- 수치 주장 검증에 테스트 시점 연산 확장(test-time scaling)을 적용한 연구(EMNLP 2025)가 있다. 단일 추론 방식보다 18.8% 개선했다고 보고한다. — [arXiv 2509.22101](https://arxiv.org/abs/2509.22101v1)

**StatCheck (프랑스, Inria CEDAR / École polytechnique)** [확인]
- 프랑스어 통계 주장 검증 시스템이다(CIKM 2022 데모, "Statistical Claim Checking: StatCheck in Action"). INSEE 자료·보고서에 비춰 통계 주장을 검증하던 이전 파이프라인을 확장해 Eurostat 전체 통계를 더하고, 주장 추출 모듈 2개를 새로 넣었다. 하루 1,500만 명 이상이 보는 프랑스어 언론사의 팩트체크 기자들과 함께 만들었다. — [IP Paris 연구 포털](https://researchportal.ip-paris.fr/en/publications/statistical-claim-checking-statcheck-in-action/), [HAL hal-03791175](https://hal-univ-lyon1.archives-ouvertes.fr/INRIA/hal-03791175v1), [TTO 2022 paper 4](https://meilu.jpshuntong.com/url-68747470733a2f2f7472757468616e6474727573746f6e6c696e652e636f6d/wp-content/uploads/2022/10/TTO_2022_paper_4.pdf)
- 공저자는 Balalau, Ebel, Galizzi, Manolescu, Massonnat 등이다. 앞선 작업으로 Tien-Duc Cao의 2019년 박사논문(르몽드 Les Décodeurs와 함께한 통계 주장 자동 검증)과 "Searching for Truth in a Database of Statistics"가 있다. — [HAL hal-01745768](https://hal.archives-ouvertes.fr/hal-01745768), [LIX 뉴스](https://www.lix.polytechnique.fr/news/205/view)
- INSEE 통계 스프레드시트를 Linked Data로 바꿔 검색 대상으로 만들었다. 즉 "통계표·원자료"를 찾는 쪽에 가깝다. — [HAL hal-01915148](https://hal.archives-ouvertes.fr/hal-01915148v1)
- 2024년 후속 연구로 정치 발언 속 통계 수치 언급(statistical entity)을 찾는 주석 데이터셋이 있다. — [Improved Detection of Statistical Entities](https://infoxsurseine.cloud.xwiki.com/2024/improved-detection-of-statistical-entities/)
- 사용자 요청의 "Tannier"(Xavier Tannier)는 이번 검색 결과에서 확인하지 못했다. 위 HAL 페이지 원문은 봇 차단으로 열리지 않았다.

**AggChecker (VLDB 2019, Jo 등) / Scrutinizer (PVLDB 2020, Karagiannis 등)** [확인]
- AggChecker는 관계형 데이터의 집계값을 말하는 자연어 주장을 원자료로 검증한다. 맞춤법 검사기처럼 데이터와 맞지 않아 보이는 구절에 표시를 한다. 기사 53건, 주장 392건으로 평가했다. — [Google Research](https://research.google/pubs/aggchecker-a-fact-checking-system-for-text-summaries-of-relational-data-sets/), [DeepAI](https://deepai.org/publication/verifying-text-summaries-of-relational-data-sets)
- Scrutinizer는 국제에너지기구(IEA) 보고서 같은 대규모 통계 주장을 사람 검증자가 SQL 질의로 바꾸도록 돕는다. 질의 조각을 제안하고, 어떤 주장부터 볼지 비용 기반으로 정한다. — [PVLDB DOI](https://doi.org/10.14778/3415478.3415520), [rmarcus dbscholar](https://rmarcus.info/dbscholar/papers/12176)
- 두 시스템 모두 **검증할 DB가 미리 주어진다고 가정한다.** 원 문서를 찾는 단계가 없다. — 위 출처들

**Aletheia (UIST 2024, Georgia Tech + Adobe Research)** [확인]
- 데이터 주장을 검증하고 증거를 표나 시각화로 보여 주는 프로토타입이다. LLM이 주장을 해석해 증거를 찾고, 20명 대상 사용자 연구를 했다. 한계로 "사용자가 고른 데이터셋에 의존"을 직접 밝힌다. — [arXiv 2409.10713](https://arxiv.org/html/2409.10713v1), [UIST24 PDF](https://faculty.cc.gatech.edu/~john.stasko/papers/uist24-factcheck.pdf)

**ClaimBuster** [일부 확인]
- 영향력 있는 엔드투엔드 팩트체크 시스템이다. QuanTemp 논문의 분석에 따르면 ClaimBuster 데이터셋(미국 대선 토론)에서 검증할 가치가 있는 주장의 약 36%가 수치 주장이다. — [arXiv 2403.17169v1](https://arxiv.org/pdf/2403.17169v1.pdf)
- ClaimBuster의 주 기능은 검증할 가치 판별(check-worthiness)이고 원 출처 위치는 찾지 않는다. [미재확인] — [ClaimBuster](https://idir.uta.edu/claimbuster/)

**표·과학 주장 검증 (TabFact, FEVEROUS, SciFact, TabVer, SciAtomic)**
- TabVer: LLM이 표 증거로 산술식을 만들어 계산한 값을 주장의 수치와 비교한다. FEVEROUS와 TabFact에서 기준 모델보다 낫다. 표에서 **계산해서 나온 수치**를 다룬다는 점이 「원래 어디서?」의 "기자 계산 수치"와 가장 가깝다. [확인] — [arXiv 2411.01093](https://arxiv.org/pdf/2411.01093)
- Atomic Reasoning(SciAtomic): 과학 표 주장 검증을 개념 맞추기 → 값 뽑기 → 수치 계산으로 나눈다. [확인] — [arXiv 2506.06972](https://arxiv.org/html/2506.06972v1)
- TabFact(위키 표 기반 주장 검증, ICLR 2020), FEVEROUS(위키 문장+표 증거, NeurIPS 2021 데이터셋), SciFact(논문 초록 근거 문장 선택, EMNLP 2020). 모두 영어이고, 증거 출처(위키·초록)가 정해진 닫힌 환경이다. [미재확인] — [TabFact arXiv 1909.02164](https://arxiv.org/abs/1909.02164), [FEVEROUS arXiv 2106.05707](https://arxiv.org/abs/2106.05707), [SciFact arXiv 2004.14974](https://arxiv.org/abs/2004.14974)
  - SciFact는 근거 **문장**(rationale)을 고르는 과제가 있어 "정확한 문장 짚기"와 닮았다. 다만 원 문서는 미리 주어진 초록 집합이다. [미재확인]

### Inferences
- 기존 수치 검증 벤치마크의 출력은 "참/거짓/상충" 판정이다. 「원래 어디서?」가 내는 "출처 관계 유형(그대로 인용 / 표현 변경 / 계산 / 통계표 인용 / 원문에 없음)"은 다른 축이다. 진실 여부가 아니라 **원문과 어떤 관계인지**를 나눈다는 점을 새로움으로 내세울 수 있다.
- StatCheck, AggChecker, Scrutinizer, Aletheia는 "통계 DB나 표에 비춰 맞는지"를 본다. 「원래 어디서?」는 "어느 보도자료·보고서 PDF의 몇 쪽 몇째 문장인가"를 찾는다. 출처 종류가 서술형 문서(PDF)이고, 쪽·문장 단위로 위치를 낸다는 점이 다르다.
- "기자 계산 수치" 감지는 TabVer, SciAtomic의 산술 검증과 닮았다. 다만 이들은 계산식이 주장과 맞는지만 확인하고, "이 수치는 원문에 없고 A÷B로 만든 값"이라고 **재료를 밝혀 주는 출력**은 없다(초록 수준 확인, 추론).

### Gaps
- Xavier Tannier의 StatCheck 관련 참여 여부, StatCheck 코드 공개 여부: 확인하지 못했다(HAL 페이지 접근 차단).
- QuanTemp 원 논문의 GitHub 주소: 이번에 확인하지 못했다(QuanTemp++만 확인).
- FEVEROUS, TabFact, SciFact, ClaimBuster의 세부 내용은 기존 지식이며 이번에 원문을 다시 보지 않았다.
- CEDAR(VLDB 2025, 검색 결과에 이름만 나옴)의 내용은 확인하지 못했다.

## Q2. 출처·유래 추적 (provenance) 연구: "Who said it, and Why?" 등

### Takeaway
문장이 어디서 왔는지를 그래프나 출처 문서로 추적하는 연구는 있다. Zhang·Ives·Roth의 ACL 2020과 ACL-IJCNLP 2021, Spangher 등의 2023 뉴스 정보원 탐지가 그 예이다. 또 원 논문의 결과와 뉴스 문장 사이 "의미 변화" 정도를 1–5점으로 매기는 데이터셋(SPICED, EMNLP 2022)이 있다. 다만 이들은 숫자에 특화되어 있지 않고, 의미 변화를 기간·대상·단위·용어 유형으로 나누지 않으며, PDF의 쪽 위치도 내지 않는다.

### Cited Findings
- "Who said it, and Why?" Provenance for Natural Language Claims (Yi Zhang, Zachary Ives, Dan Roth, ACL 2020, 4416–4426쪽): 자연어 주장의 **출처 그래프**(어디서 나왔고 어떻게 바뀌었는지)를 형식적으로 정의한 첫 연구라고 밝힌다. 출처 추론을 주로 정보추출로 풀고 텍스트 함의(entailment) 모델을 쓴다. 벤치마크 2개에서 초기 성과를 보이고, 주장 검증에도 효과가 있다고 보고한다. [확인] — [ACL Anthology](https://aclanthology.org/2020.acl-main.406), [ACL 2020 virtual](https://virtual.acl2020.org/paper_main.406.html)
- 후속 "What is Your Article Based On? Inferring Fine-grained Provenance"(ACL-IJCNLP 2021, 같은 저자)는 PolitiFact 기사로 만든 Politi-Prov 데이터셋을 쓴다. [확인: 저자 페이지 수준] — [ACL Anthology Zachary Ives](https://aclanthology.org/people/zachary-ives)
- Identifying Informational Sources in News Articles (Spangher 등, 2023): 뉴스 문장이 어느 정보원에서 왔는지(명시적·암묵적 귀속) 주석했다. 정보원 탐지 일치도 κ=.85, 귀속 일치도 κ=.82이고, 기사 문장의 약 50%가 정보원 문장이다. [확인] — [arXiv 2305.14904](https://arxiv.org/pdf/2305.14904)
- SPICED (Wright, Pei, Jurgens, Augenstein, EMNLP 2022): 논문 원문의 결과 문장과 뉴스·트윗 문장 6,000쌍에 정보 일치 점수(IMS, 1–5점)를 붙였다. 분야는 컴퓨터과학·의학·생물·심리학이다. **보도자료와 과학기술 매체가 일반 뉴스보다 정보 변화가 적다**는 결과를 보고한다. 데이터는 Hugging Face(copenlu/spiced)에 공개되어 있다(카드 기준 학습 4,721건). [확인] — [arXiv 2210.13001](https://arxiv.org/abs/2210.13001), [ACL Anthology](https://aclanthology.org/2022.emnlp-main.117), [HF 데이터셋 카드](https://huggingface.co/datasets/copenlu/spiced/blob/main/README.md)
- 2026년 관련 연구 [확인]
  - ProvenanceGuard(arXiv 2606.18037): 주장이 어딘가에서는 뒷받침되지만 **엉뚱한 출처로 귀속된** 오류를 잡는다. 의료 분야 MCP 에이전트 기록으로 평가했고 출처 정확도는 0.858이다. — [arXiv 2606.18037](https://arxiv.org/abs/2606.18037)
  - LLM 에이전트의 증거 추적 서베이(2026): 긴 실행에서 주장 단위 출처 추적은 아직 풀리지 않은 문제라고 한다. — [arXiv 2606.04990](https://arxiv.org/html/2606.04990v6)
  - 코딩 에이전트가 공식 통계(Eurostat)를 재현할 수 있는지 본 2026 연구: 정확한 메타데이터를 주면 정답률이 27.8%에서 51.1%로 오른다. — [arXiv 2609.22222](https://arxiv.org/pdf/2609.22222)
  - Document Attribution(2025): 생성 결과를 원 문서로 거슬러 귀속하는 문제를 텍스트 함의로 다룬다. — [arXiv 2505.06324](https://arxiv.org/html/2505.06324v1)

### Inferences
- "출처 추적"이라는 문제 설정 자체는 2020년부터 있었다. 그래서 「원래 어디서?」의 새로움은 "출처 추적 최초"라고 말하면 안 된다. 다음을 조합해 주장하는 것이 안전하다. (1) 통계 수치에 특화, (2) 1차 문서(보도자료·보고서 PDF)의 쪽·문장 위치, (3) 기간·대상·단위·용어별 변화 유형, (4) 계산 수치의 재료 제시, (5) 한국어.
- SPICED는 "원문 vs 뉴스 문장의 의미 변화"를 다룬 가장 가까운 선행연구이다. 「원래 어디서?」의 "표현 변경" 분류는 SPICED의 1–5 연속 점수를 **원인 유형별로 나눈 확장**이라고 위치 지을 수 있다.
- ProvenanceGuard의 "출처 오귀속" 개념은 "원문에 없음 / 다른 자료에서 옴" 판정과 이어진다.

### Gaps
- Politi-Prov 데이터·코드의 GitHub 공개 여부는 찾지 못했다.
- "quote origin tracing"(인용문 원출처 추적)만 다룬 별도 연구는 이번 검색에서 찾지 못했다.
- 2025–2026년에 나온, 뉴스 통계 문장 → 원 보고서 PDF 쪽·문장 위치를 직접 다루는 논문은 찾지 못했다(extended 검색 2회). 없다고 단정할 수는 없다.

## Q3. 한국어 팩트체크 데이터셋·연구 (한국어 숫자 포함)

### Takeaway
한국어로 된 **수치 주장 검증 데이터셋은 찾지 못했다.** 확인한 한국어 자원은 다음과 같다. SNU 팩트체크를 긁어 만든 소규모 가짜뉴스 데이터, 네이버가 함께한 사실검증 데이터 증강 연구(2021), 환각 벤치마크(K-HALU, ICLR 2025), 사실성 QA(KoSimpleQA, 2025), FEVER 기계번역(NanoBEIR-ko), 공공데이터포털의 LLM 출력 원자 사실 라벨 데이터. 원 출처 문서를 찾아 위치를 짚는 한국어 연구는 확인되지 않았다.

### Cited Findings
- SNU 팩트체크 플랫폼은 발언자, 주장, 판정(5단계), 근거, 참고자료, 주장 출처를 제공한다. — [factcheck.snu.ac.kr](https://factcheck.snu.ac.kr/home/about)
- 한 연구는 SNU 팩트체크를 크롤링해 기사 528건(2017-03~2020-05)으로 한국어 가짜뉴스 데이터셋을 만들고 판정을 참/거짓 2개로 묶었다(교차언어 전이학습). — [arXiv 2208.12482](https://arxiv.org/pdf/2208.12482)
- 2023년 11월 네이버가 SNU 팩트체크 재정 지원을 끝냈고, 센터장은 서비스 중단 가능성을 언급했다. 현재 운영 상태는 확인하지 못했다. — [Poynter](https://poynter.org/?p=1084464)
- 생성 언어모델로 한국어 사실검증 학습 데이터를 늘리는 준지도 증강 연구(2021, 한글 및 한국어 정보처리 학술대회, 네이버 공저)가 있다. — [koreascience](https://koreascience.kr/article/CFKO202130060782846.pdf)
- K-HALU(ICLR 2025): 한국 뉴스·잡지·책으로 만든 한국어 환각 탐지 벤치마크이다. 주장 검증용 지지/반박 라벨 데이터셋은 아니다. — [ICLR 2025](https://proceedings.iclr.cc/paper_files/paper/2025/hash/cfcadfe84ee49908cde1fc2992c38d20-Abstract-Conference.html)
- KoSimpleQA(2025-10): 한국 문화 지식 중심의 사실성 QA 벤치마크이다. — [arXiv 2510.18368](https://arxiv.org/html/2510.18368v1)
- NanoBEIR-ko NanoFEVER: FEVER를 한국어로 기계번역한 소규모 검색 과제(질의 50개)이다. — [HF leaderboard 문서](https://hakari-bench-leaderboard.hf.space/docs/benchmark-tasks/MNanoBEIR/NanoBEIR-ko__NanoFEVER)
- Hugging Face jonghhhh/claim_factcheck: 한국어 검증 대상 문장 분류기이다. 판정은 하지 않고, 학습 데이터 약 22,500건은 기계번역이다. — [HF README](https://huggingface.co/jonghhhh/claim_factcheck/blob/main/README.md)
- 공공데이터포털에 AI 생성 한국어 문장을 단일 사실(atomic fact)로 나누고 참/거짓 라벨과 Python 평가 코드를 붙인 데이터가 있다. — [data.go.kr 15149192](https://www.data.go.kr/data/15149192/fileData.do)
- 한국어 검증 필요 문장 탐지 모델을 LLM·RAG와 묶어 제21대 대선 후보 토론에 적용한 연구가 있다(데이터 공개 여부는 확인 못 함). — [koreascience JAKO202316061674328](https://koreascience.or.kr/article/JAKO202316061674328.pdf)

### Inferences
- 한국어 + 수치 + 원 출처 위치라는 조합은 학술 자원이 사실상 비어 있는 영역으로 보인다. 「원래 어디서?」의 새로움 주장 중 가장 단단한 근거가 된다(추론. "찾지 못함"이지 "없음 증명"은 아니다).
- 한국어 수치 표현에는 특유의 어려움이 있다. 예: 만·억 단위, "%p" 대 "%", "전년 동기 대비", "역대 최대". 이를 다룬 연구는 이번 조사에서 찾지 못했다. 직접 만든 평가셋 자체가 기여가 될 수 있다.

### Gaps
- AI Hub(aihub.or.kr)에 팩트체크·허위정보 데이터셋이 있는지는 검색으로 확인하지 못했다. 사이트에서 직접 검색해야 한다.
- KAIST, 서울대 등 국내 연구실의 한국어 수치 주장 연구, KCI 논문은 이번 검색에서 나오지 않았다.

## Q4. 오픈소스 팩트체크 파이프라인 (OpenFactCheck, Loki, FacTool, FIRE, Veracity)

### Takeaway
OpenFactCheck, Loki 같은 오픈소스 파이프라인은 "주장 분해 → 검색 질의 생성 → 웹 증거 검색 → 판정" 구조이다. 수치 주장 전용 처리, 1차 문서(PDF) 안 쪽·문장 위치 찾기, 의미 변화 유형 분류를 한다는 설명은 확인하지 못했다. 주 목적도 LLM 출력의 사실성 평가에 가깝다.

### Cited Findings
- OpenFactCheck(MBZUAI 등, EMNLP 2024 데모)는 모듈 3개로 이루어진다. ResponseEval(맞춤형 팩트체커 구성과 문서 속 주장 검증), LLMEval(LLM 사실성 평가), CheckerEval(팩트체커 비교 평가)이다. Python 라이브러리와 웹 서비스로 공개했고 GitHub은 mbzuai-nlp/openfactcheck이다. FIRE, Factcheck-GPT 같은 검증기를 묶어 쓴다. [확인] — [arXiv 2408.11832](https://arxiv.org/pdf/2408.11832), [EMNLP 2024 demo](https://aclanthology.org/2024.emnlp-demo.23.pdf), [arXiv 2405.05583](https://arxiv.org/html/2405.05583v3)
- Loki: 긴 글을 주장으로 나누기, 검증 가치 판별, 질의 생성, 증거 검색, 검증의 5단계 오픈소스 도구이다. 지연시간·비용 효율과 사람 판단 보조에 초점을 둔다. [확인] — [arXiv 2410.01794](https://arxiv.deeppaper.ai/papers/2410.01794v1?locale=en)
- FIRE(Xie 등, 2024): 반복 검색으로 시간·비용을 줄인 검증기라고 OpenFactCheck에서 소개한다. 수치 처리 여부는 확인하지 못했다. — [arXiv 2405.05583](https://arxiv.org/html/2405.05583v3)
- FacTool(2023): 지식 QA·코드·수학·논문 인용 등 여러 분야의 LLM 출력 사실성을 도구로 확인하는 프레임워크이다. [미재확인] — [arXiv 2307.13528](https://arxiv.org/abs/2307.13528)

### Inferences
- 오픈소스 파이프라인의 증거 단위는 웹 검색 결과 조각이다. 1차 문서를 내려받아 쪽 번호를 붙여 인용하는 기능은 기본이 아닌 것으로 보인다(검색 결과 기준 추론).
- 이 도구들은 「원래 어디서?」의 하위 단계(주장 분해·검색)를 짤 때 참고하거나 비교 기준(baseline)으로 쓸 수 있다. OpenFactCheck의 CheckerEval 구조는 평가 설계에 참고할 만하다.

### Gaps
- "Veracity"라는 오픈소스 팩트체크 시스템은 이번 검색에서 확인하지 못했다.
- FIRE, Loki의 GitHub 저장소 주소와 수치 처리 여부는 원문을 열어 보지 못했다.
